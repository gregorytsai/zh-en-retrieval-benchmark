METHODS / REPRODUCIBILITY

How the test works, and what it can establish.

The original five tasks are retained; ACORD has a new 28-setup retest. Inspect all task scores, data and code.

How is the homepage mean calculated?

Average queries within each task, then assign each of three MLQA directions, two MIRACL languages and ACORD weight 1/6. Six-task score = (original-five mean × 5 + ACORD) / 6. MLQA contributes 50%, MIRACL 33.3%, legal 16.7%; this is a chosen weighting, not equal dataset-family weighting or production traffic. The original-five mean remains selectable. All 28 setups are complete; missing scores are never zero-filled.

What does consistent testing mean?

Queries, corpus, qrels and model weights are fixed within each task. Three rerankers share each embedder’s ordered Top50, while embedders may retrieve different candidates. ACORD first removes unknown qrel pairs, retaining explicit zero grades, then selects Top50; other tasks use unfiltered retrieval Top50. Production RAG lacks this judged-membership information, so the aggregate is a benchmark index, not a deployment hit rate.

Data scope and bilingual direction

MLQA: 504 Chinese-to-English, 504 Chinese-to-Chinese and 1,148 English-to-English queries. eng-zho means English context / Chinese question, not the reverse. MIRACL has 200 queries per language with 3,786 Chinese and 7,921 English passages, a union of dev-judged passages rather than full million-scale corpora. ACORD has 57 queries, 3,931 clauses and 61,988 judged pairs at revision 7ba1c6f2e0baaa32e78c78c2b02e9c57b102af4e. Current rows total 73,164 = 71,568 retained + 1,596 retested; this is not the independent sample count.

What does latency include?

Original-five timing includes query embedding, search and reranking; new ACORD timing separately includes judged filtering. Warm timing excludes model loading, indexing and answer generation; loopback HTTP is included in model stages. Individual tasks show mean/p50/p95, without averaging percentiles. Six-task latency is not pooled. One accepted measurement per query is not a fixed 30-query × 3-repeat load test and cannot guarantee production latency. Weights match, but not all historical runtime-library hashes are available.

Do small differences establish a winner?

The leading six-task scores differ by about 0.0006; several ACORD 4B-reranker scores are also close. No global bootstrap or multiplicity adjustment supports a reliable/significant winner. ACORD source-query dependence is unverified, so no new bootstrap interval is reported; original-five paired intervals do not extend to the six-task index. Datasets, candidate constraints and task weights affect rankings.

Published findings and this benchmark’s contribution

Qwen reports higher 4B than 0.6B reranking scores on MTEB-R, CMTEB-R and MMTEB-R; the five-task mean for each local embedder shows the same direction. Qwen uses Top100 from Qwen 0.6B; this study uses each embedder’s Top50, preventing direct absolute-score comparison. The contribution is a full local Q8_0 28-setup matrix, Chinese-to-English alongside same-language retrieval, and measured size/latency tradeoffs. Cross-language Top-1 is 86.31% for Qwen 0.6B + 0.6B versus 81.94% for 8B alone. The reverse direction was not tested; no first-discovery claim is made.

Verification and known limitations

Publication checks verified 102 source-file hashes, ten model weights and all queries/corpus/qrels. Independent per-query validation passed: 28 setups, 1,596 rows, 399 candidate lists, 59,850 pair scores; no missing, duplicate, nonfinite or accepted-error rows. The source reports 69 historical judged-tail differences, all beyond Top50, four above the diagnostic epsilon; their cause is unresolved, not established as floating-point noise.

The delivered macOS environment reports 107 passing tests. This Windows recheck passed 87 tests, with seven test modules unable to import Unix fcntl dependencies. The data validator passes on Windows; publication work did not rerun model inference.
