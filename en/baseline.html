01 / KEY FINDINGS

Spend extra compute where it helps.

These are observations from this dataset, not universal rules for every knowledge base.

01

With a larger reranker,
five embedders tie on Top-1.

281 / 300

All five core embedders paired with the Qwen 4B reranker retrieve a relevant document first for 281 of 300 tasks: 93.67%. Smaller combinations are worth evaluating before moving straight to an 8B embedder.

Equal totals do not mean identical answers on every task or identical rankings. MRR and nDCG still differ.

02

when Chinese queries search English documents.

Chinese → English+10.2 pp
English → English+0.4 pp

Mean gains by direction when upgrading the Qwen reranker from 0.6B to 4B. Mean reranking time rises from 1.16 s to 6.29 s.

Match a configuration to your hardware

Entry-level devices, e.g. 8 GB

Start by evaluating a standalone Granite, Gemma 2 or BGE-M3 embedder. Adding a reranker depends on available memory, document length and service configuration.

Mid-range devices, e.g. 16 GB

Try a small embedder with the 0.6B or BGE reranker. Before trying a 4B reranker, check peak runtime memory and latency.

32 GB or more / workstations

Evaluate a 4B reranker. If you only need vector search, the 8B embedder had the best overall quality in this run. More memory does not guarantee a higher hit rate.

These are selection starting points, not measurements on those devices. CPU memory, discrete GPU VRAM and Apple unified memory are not interchangeable. M3 Ultra timings should not be treated as expected laptop performance.

Narrow the options by weight budget

Only measured combinations are compared. Ties favor the faster configuration. No speed estimates are made for other hardware.

04 / THE METHOD IN A FEW SENTENCES

The same queries.
Different models.

We select 100 fixed queries per direction from MLQA validation and keep each full corpus: 430, 443 and 978 documents. The embedder retrieves 50 candidates, then we compare results with and without reranking.

Only accepted guarded v3 records are included. With 100 queries per direction, one task changes the result by one percentage point. Small differences may change with the query set. English-to-Chinese retrieval, large knowledge bases and concurrent serving were not tested.
